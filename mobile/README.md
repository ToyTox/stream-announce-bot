# Мобильное приложение

Самостоятельный каркас на React Native, Expo SDK 58 и TypeScript. Основная платформа — Android; iOS пока без проверки на устройстве. У приложения собственные зависимости и lock-файл; корневые команды относятся к боту и настольному приложению.

При запуске приложение читает сохранённое подключение из защищённого хранилища. Без записи открывается «Сопряжение», все пять вкладок доступны без сети. С записью сначала выполняется авторизованный `GET /api/v1/info`; разделы открываются после проверки API версии 1. Версия самого приложения бота может быть пустой и не влияет на совместимость. Выбранный раздел выделяется, системная кнопка возврата на Android открывает предыдущую посещённую вкладку; когда история исчерпана, возврат передаётся системе. Светлая и тёмная темы следуют системе, меняются без перезапуска и сохраняют выбранный экран. Если тема системы неизвестна, используется светлая.

## Подключение и токен

Адрес содержит `/api/v1`, не содержит учётных данных, параметров или фрагмента. Токен устройства отправляется только заголовком `Authorization: Bearer …`. Общие типы берутся из `shared/api-v1.d.ts`; клиент пока выполняет только проверку подключения, рабочие операции не добавлены.

Адрес и токен хранятся одной записью в `expo-secure-store`, без открытой резервной копии. Настройка исключает защищённые данные из резервной копии Android; на iOS запись доступна при разблокированном устройстве и не переносится на другое устройство. Биометрия и дополнительные разрешения не используются. Отсутствие записи, повреждение и отказ чтения, записи или удаления различаются. На операцию хранилища отводится 5 секунд. При истечении ожидания запись или удаление могут завершиться позже; приложение сообщает об ошибке, последовательность операций сохраняется, успех не показывается заранее.

На сетевую проверку отводится 10 секунд вместе с чтением тела. Потеря сети и истечение ожидания показывают «Бот недоступен» с кнопкой «Повторить». Отдельно отображаются непринятый токен (401), запрет доступа (403), ограничение частоты (429), прочие ошибки HTTP, некорректный ответ, несовместимость API и ошибка хранилища. `Retry-After` ограничивает момент повтора; автоматических повторов нет. Сетевой сбой не удаляет сохранённые данные. Повторы во время проверки игнорируются; ответы после смены подключения, удаления или закрытия приложения не возвращают старое состояние. Навигация остаётся смонтированной, сохраняя тему и историю вкладок.

Кнопка «Удалить токен с телефона» доступна после подключения и на экране проверки или ошибки. Это локальное удаление, а не отзыв устройства на сервере. При отказе удаления приложение предупреждает, что токен может оставаться на телефоне, и предлагает повтор. Токен и исходные сообщения сетевых, серверных и системных ошибок не выводятся в интерфейс или логи.

Для будущего сопряжения подготовлен `useConnection().connect(credentials)`: проверка формата, защищённое сохранение и проверка `/info`. Формы ввода токена, сканера и демонстрационного подключения нет. Чистая установка пока не создаёт подключение; настоящий пользовательский поток относится к пункту 13.

Обычный HTTP может блокироваться платформой: iOS требует исключений политики транспорта, Android начиная с API 28 по умолчанию ограничивает незашифрованный трафик. Текущий клиент среды разработки и будущая нативная сборка могут вести себя по-разному. Используйте доступный телефону HTTPS-адрес; настройки будущего нативного выпуска в этой задаче не добавляются. [Ограничения сети](https://reactnative.dev/docs/network), [контракт хранилища](https://docs.expo.dev/versions/latest/sdk/securestore/).

## Установка и запуск

Нужен Node.js 22.13 или новее в ветке 22, либо совместимая версия из `engines` в `package.json`. Команды выполняются из корня репозитория:

```sh
npm --prefix mobile ci
npm --prefix mobile start
```

Установите совместимый с SDK 58 клиент Expo Go на тестовый телефон и откройте показанный код. Телефон и компьютер должны иметь доступ друг к другу по локальной сети. Для уже запущенного Android-эмулятора или подключённого телефона с настройкой отладки используйте `npm --prefix mobile run android`; для запущенного симулятора iOS на Mac — `npm --prefix mobile run ios`. Эти команды запускают сервер разработки и открывают клиент, установщик не собирается. Сам бот для проверки каркаса не нужен.

## Проверки

```sh
npm --prefix mobile run typecheck
npm --prefix mobile test -- --runInBand
cd mobile
CI=1 npx --no-install expo install --check
npx --no-install expo export --platform android
```

Последняя команда создаёт пакет JavaScript и ресурсов в `mobile/dist/`, без нативного проекта и установщика. Тесты используют настоящую навигацию, подменяют сеть и защищённое хранилище, тему, кнопку возврата и безопасные области. Проверяются восстановление, все состояния подключения, повторы и удаление, поздние ответы и отсутствие секретов в ошибках, а также все пять заглушок, переходы, возврат и смена темы без потери раздела. Настройки Jest ограничены `mobile/tests/`; корневые тесты запускаются отдельно через `npm test`.

Для ручной проверки без записи откройте каждый раздел, пройдите назад системной кнопкой до стартового экрана, переключите системную тему при открытом приложении. Проверьте читаемость, выбранную вкладку и отступы от вырезов, статусной панели и нижней системной панели в обоих оформлениях, включая увеличенный размер текста. В окружении с уже сохранённой защищённой записью перезапустите приложение, затем временно отключите доступ к сети бота, повторите проверку после восстановления сети и удалите локальный токен. После следующего запуска должно открыться «Сопряжение» без запроса к боту. Не копируйте токен в команды, логи, снимки экрана или отчёты. Пока поток сопряжения не реализован, восстановление и удаление проверяются автоматически с подменённым хранилищем; на устройстве они, темы и безопасные области не проверены.

## Структура

| Путь | Назначение |
|------|------------|
| `index.ts`, `App.tsx` | Регистрация приложения, системные панели, тема и безопасная область |
| `src/navigation.tsx` | Пять вкладок и история возврата |
| `src/screens.tsx` | Названия разделов и заглушки |
| `src/theme.ts` | Палитры и подписка на тему системы |
| `src/api.ts` | Авторизованная проверка API, ожидание и безопасные ошибки |
| `src/credentials.ts` | Защищённая запись адреса и токена |
| `src/connection.tsx` | Восстановление, повтор, смена и удаление подключения |
| `tests/` | Проверки интерфейса и системных изменений |
| `app.json`, `tsconfig.json`, `jest.config.cjs` | Настройки приложения, типов и тестов |

## Ограничения

Реализованы каркас и основа подключения из пунктов 11–12 [мобильного плана](../docs/mobile-app-plan.md). Сопряжения, сканера, рабочих действий, фото и уведомлений пока нет. Успех подключения означает только проверенную совместимость API, не отправку анонса. Поддержка системной темы Android настроена через `userInterfaceStyle: automatic` и `expo-system-ui`; цвета системных панелей согласованы с темой, содержимое учитывает безопасную область. Распространение и нативные сборки относятся к последующим задачам.

Контракты: [навигация](https://docs.expo.dev/develop/app-navigation/), [системная тема](https://docs.expo.dev/develop/user-interface/color-themes/), [тестирование](https://docs.expo.dev/develop/unit-testing/), [команды](https://docs.expo.dev/more/expo-cli/).
