# План: нативное мобильное приложение

Этот документ описывает, как добавить к stream-announce-bot мобильное приложение для Android и iOS. Он составлен до начала работы: кода мобильного приложения пока нет.

## Зачем

Сейчас ботом можно управлять из веб-панели и десктопного приложения на компьютере, где он запущен, и командами в личке Telegram. Мобильное приложение нужно, чтобы с телефона:

- видеть, идёт ли эфир и в порядке ли проверка площадок;
- задавать текст и картинку для анонса, в том числе фото из галереи;
- менять основные настройки;
- получать уведомления об анонсе, окончании эфира и ошибках.

## Исходные ограничения

**Телефон — пульт, а не дом для бота.** Бот раз в минуту опрашивает площадки. iOS останавливает фоновые задачи приложения, Android ограничивает их и тратит на них батарею. Поэтому бот продолжает работать на компьютере (Mac или Windows) или, в будущем, на сервере, а приложение только подключается к нему.

**Бот сейчас недоступен снаружи.** Панель слушает только `127.0.0.1` и отклоняет запросы с чужих адресов. Телефону нужен отдельный защищённый путь до бота.

**Без оплаты есть ограничения:**

| | Android | iOS |
|---|---|---|
| Распространение | Бесплатно: файл `.apk` в GitHub Releases | Без Apple Developer ($99/год) — только установка через Xcode с бесплатным Apple ID, приложение перестаёт работать через 7 дней |
| Push-уведомления | Бесплатно (Firebase Cloud Messaging) | Только с платным аккаунтом Apple Developer |
| Публикация в магазине | Google Play — $25 разово (необязательно) | App Store — входит в $99/год |

На первом этапе основная платформа — Android. iOS — при появлении платного аккаунта.

## Шаги

### 0. Предусловия

Должны быть выполнены шаги 1–3 развития проекта:

1. **Веб-панель** — HTTP API в `src/web/server.ts`. Мобильное приложение будет использовать те же маршруты.
2. **Десктопное приложение** — бот работает в фоне на компьютере, запускается при входе в систему.
3. **Установщики в GitHub Releases** — сборка в GitHub Actions по тегу версии. В тот же релиз будет добавляться `.apk`.

### 1. API для удалённых клиентов

- Стабильная версия API `/api/v1/*` поверх существующих маршрутов: статус, текст, картинка, предпросмотр, настройки, лог. Старые `/api/*` остаются для панели.
- Общие типы запросов и ответов выносятся в пакет `shared/` (npm workspaces), чтобы бот, панель и приложение использовали одни определения.
- Описание контракта в `docs/api-v1.yaml` (OpenAPI).
- Загрузка картинки из приложения идёт тем же путём, что из панели: бот отправляет её в личку Telegram и сохраняет `file_id`.

### 2. Авторизация устройств

- **Сопряжение:** в панели кнопка «Подключить телефон» показывает QR-код с адресом бота и одноразовым кодом (действует 5 минут). Приложение сканирует QR-код и обменивает код на долгоживущий токен устройства.
- Токены хранятся в базе только в виде хэша. В панели есть список подключённых устройств с кнопкой «Отключить».
- Каждый удалённый запрос передаёт `Authorization: Bearer <токен>`. Без токена или с отозванным токеном — 401. Есть ограничение частоты запросов.
- Проверки localhost для панели в браузере остаются как есть.

### 3. Удалённый доступ

- **Tailscale** (бесплатно для личного использования): компьютер и телефон входят в одну приватную сеть. Бот не открыт в интернет, телефон обращается к нему по адресу внутри сети Tailscale.
- Новая настройка `REMOTE_ENABLED` (по умолчанию выключена): сервер дополнительно слушает адрес Tailscale и принимает там только `/api/v1` с токеном.
- Шифрование обеспечивает сам Tailscale, поэтому HTTPS-сертификат не нужен.
- Альтернативы на будущее: Cloudflare Tunnel (нужен свой домен, ~$10/год) или перенос бота на сервер. Тогда HTTPS обязателен.

### 4. Уведомления

- **Android:** Firebase Cloud Messaging. Приложение при сопряжении передаёт боту push-токен, бот шлёт уведомления по событиям `announced`, `finished`, `announce_failed`. Эти события уже есть в `AnnouncerDeps.onEvent`, их использует десктопное приложение.
- **iOS** без платного аккаунта: push недоступен, остаются уведомления в Telegram.

### 5. Мобильное приложение

- **Стек:** React Native + Expo, TypeScript, общие типы из `shared/`.
- **Экраны:**
  - **Сопряжение** — сканер QR-кода, повторное подключение, отключение.
  - **Статус** — эфир, площадки, ошибки, кнопки «Проверить сейчас» и «Тестовое сообщение».
  - **Сообщение** — текст в анонс, своё превью (фото из галереи или камеры), предпросмотр анонса и сообщения об окончании.
  - **Настройки** — основные поля: тестовый режим, площадки, тайминги. Секреты с телефона не меняются.
  - **Лог** — последние строки.
- Светлая и тёмная тема по системе.
- **Если бот недоступен** (компьютер выключен или нет сети), приложение показывает это явно, а не бесконечную загрузку.

### 6. Сборка и выпуск

- **Android:** `expo prebuild` + Gradle в GitHub Actions в том же workflow, что и десктоп (`.github/workflows/release.yml`). `.apk` подписывается ключом из секретов репозитория и прикладывается к релизу рядом с `.dmg` и `.exe`.
- **iOS:** локальная сборка через Xcode для личного использования. TestFlight и App Store — после покупки Apple Developer.
- Версия приложения совпадает с версией бота. Приложение проверяет совместимость по версии API при подключении.

### 7. Тесты

- **API v1 и сопряжение:** vitest — коды, токены, отзыв, 401 без токена, ограничение частоты.
- **Приложение:** Jest + React Native Testing Library — экраны и обработка недоступности бота.
- **Вручную:** Android-телефон через Tailscale — сопряжение, все экраны, загрузка фото, push на тестовом эфире (`DRY_RUN=true`).

| **Итого** | **~3 недели** |

## Риски

- **Безопасность.** Открывая бота наружу, легко ошибиться. Поэтому доступ только через приватную сеть и только с токеном, а секреты через API не отдаются.
- **iOS без платного аккаунта** почти непригоден: переустановка каждые 7 дней, нет push.
- **Компьютер с ботом должен быть включён** и не спать, иначе приложению не к чему подключаться. Это решает только перенос бота на сервер.

## Более дешёвая альтернатива

**Telegram Mini App** — 3–5 дней.

- Панель открывается прямо в Telegram на телефоне, вход по аккаунту Telegram, без паролей и сопряжения.
- Не нужны магазины приложений и платные аккаунты, одинаково работает на Android и iOS.
- Интерфейс переиспользуется из веб-панели.
- Нужен публичный HTTPS-адрес бота: Cloudflare Tunnel с компьютера или сервер.
- Push-уведомления заменяют сообщения бота в Telegram.

Если нужен только удобный пульт с телефона, стоит начать с Mini App, а к нативному приложению переходить, когда понадобятся возможности, которых в Telegram нет.
