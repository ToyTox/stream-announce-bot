# План: нативное мобильное приложение

Этот документ описывает, как добавить к stream-announce-bot мобильное приложение. Решение принято: нативное приложение для Android на React Native + Expo, iOS — по возможности. Код мобильного приложения пока не начат. Завершены задачи 1–10 и 10a главы A, включая `/api/v1`, реестр устройств, одноразовое сопряжение, QR, отзыв устройств, квоты и удалённый доступ через Tailscale. Телефон может проверить обмен кода и API обычным HTTP-клиентом. [Порядок проверки](development.md#удалённый-доступ-через-tailscale)

## Зачем

Бот шлёт анонсы в Telegram и/или Discord (достаточно одной площадки доставки). Сейчас им можно управлять из веб-панели и десктопного приложения на компьютере, где он запущен, а при включённом Telegram — ещё и командами в личке. Без Telegram (режим «только Discord») команд нет, остаются панель и десктоп. Мобильное приложение нужно, чтобы с телефона:

- видеть, идёт ли эфир и в порядке ли проверка площадок;
- задавать текст и картинку для анонса, в том числе фото из галереи;
- менять основные настройки;
- получать уведомления об анонсе, окончании эфира и ошибках.

## Исходные ограничения

**Телефон — пульт, а не дом для бота.** Бот раз в минуту опрашивает площадки. iOS останавливает фоновые задачи приложения, Android ограничивает их и тратит на них батарею. Поэтому бот продолжает работать на компьютере (Mac или Windows) или, в будущем, на сервере, а приложение только подключается к нему.

**Панель доступна только на компьютере с ботом.** Она слушает `127.0.0.1` и принимает Host `localhost` или `127.0.0.1` с портом панели. Если есть Origin, он должен соответствовать одному из этих адресов. У телефона отдельный вход через Tailscale с проверками Host, Origin и токена устройства.

**Без оплаты есть ограничения:**

| | Android | iOS |
|---|---|---|
| Распространение | Бесплатно: файл `.apk` в GitHub Releases | Без Apple Developer ($99/год) — только установка через Xcode с бесплатным Apple ID, приложение перестаёт работать через 7 дней |
| Push-уведомления | Бесплатно (Firebase Cloud Messaging) | Только с платным аккаунтом Apple Developer |
| Публикация в магазине | Google Play — $25 разово (необязательно) | App Store — входит в $99/год |

На первом этапе основная платформа — Android. iOS — при появлении платного аккаунта.

## Шаги

### 0. Предусловия

Всё перечисленное уже есть в проекте:

1. **Веб-панель** — HTTP API в `src/web/server.ts`. Мобильное приложение будет использовать те же маршруты.
2. **Десктопное приложение** — бот работает в фоне на компьютере, запускается при входе в систему (`desktop/main.ts`).
3. **Установщики в GitHub Releases** — сборка в GitHub Actions по тегу версии (`.github/workflows/release.yml`). В тот же релиз будет добавляться `.apk`.
4. **Discord и режим без Telegram** — анонсы можно слать в Discord, а Telegram необязателен, если задан Discord. Приложение не должно предполагать, что Telegram включён.

### 1. API для удалённых клиентов

- Стабильная версия API `/api/v1/*` поверх существующих маршрутов `/api/*` из `src/web/server.ts` (маршруты уже сделаны): информация о версии API (`GET /api/v1/info`, только в v1), статус (`GET /api/status`), проверка сейчас (`POST /api/probe`), тестовое сообщение (`POST /api/test-message`), тестовые анонсы (`POST /api/test-announce/telegram` и `/discord`), текст (`GET`/`PUT`/`DELETE /api/text`), статические ссылки анонса (`GET`/`PUT /api/links`), картинка (`PUT`/`DELETE /api/image`, `GET /api/image/file`), предпросмотр (`GET /api/preview`), настройки (`GET`/`PUT /api/settings`), лог (`GET /api/logs`). Старые `/api/*` остаются для панели.
- Описание контракта в `docs/api-v1.yaml` (OpenAPI).
- Загрузка картинки из приложения идёт тем же путём, что из панели (`PUT /api/image`, логика хранения в `src/announceImage.ts`): картинка хранится локально и работает без Telegram. В личку админу она уходит, только если Telegram включён и задан админ. `/api/v1` использует тот же путь.
- **Общие типы** запросов и ответов вынесены в [`shared/api-v1.d.ts`](../shared/api-v1.d.ts) после описания контракта OpenAPI и до создания `mobile/`. Проверка 10a до мержа включает `npm run build:desktop`, `npm run dist:mac` и `npm run dist:win`, а также состав `app.asar` и распакованный бинарник базы.

### 2. Авторизация устройств

- **Сопряжение:** в панели кнопка «Подключить телефон» показывает QR-код с адресом бота и одноразовым кодом (действует 5 минут). Приложение сканирует QR-код и обменивает код на долгоживущий токен устройства.
- Токены хранятся в базе только в виде хэша. В панели есть список подключённых устройств с кнопкой «Отключить».
- Для удалённого API нужен `Authorization: Bearer <токен>`. Первое сопряжение использует точный `POST /api/v1/pair` с одноразовым кодом. Для остальных запросов отсутствующий или отозванный токен в пределах квоты даёт 401. На localhost заголовок по-прежнему необязателен.
- Проверки localhost для панели в браузере остаются как есть.

### 3. Удалённый доступ

- **Tailscale** (бесплатно для личного использования): компьютер и телефон входят в одну приватную сеть. Бот не открыт в интернет, телефон обращается к нему по адресу внутри сети Tailscale.
- `REMOTE_ENABLED` по умолчанию выключен. При полном запуске CLI или desktop с `REMOTE_ENABLED=true` сервер открывает `/api/v1` на подтверждённом IPv4 Tailscale и фактическом порту панели. Утрата адреса или отказ клиента закрывают удалённый вход и скрывают QR.
- API использует HTTP внутри шифрованного туннеля Tailscale. Доступ с телефона зависит от правил tailnet и брандмауэра. [Настройка и диагностика](development.md#удалённый-доступ-через-tailscale)
- Альтернативы на будущее: Cloudflare Tunnel (нужен свой домен, ~$10/год) или перенос бота на сервер. Тогда HTTPS обязателен.

### 4. Уведомления

- **Android:** Firebase Cloud Messaging. Приложение при сопряжении передаёт боту push-токен, бот шлёт уведомления по событиям `announced`, `finished`, `announce_failed`. Эти события приходят через тот же `onEvent`.
- **iOS** без платного аккаунта: push недоступен. Уведомления дублируются сообщениями в Telegram, только если Telegram включён. В режиме «только Discord» уведомлений на iOS нет: приложение показывает актуальный статус при открытии.
- **Источник событий:** колбэк `onEvent` в `startBot` (`src/bot.ts`) и `AnnouncerDeps` (`src/announcer.ts`), его уже использует `desktop/main.ts`.

### 5. Мобильное приложение

- **Стек.** React Native + Expo и TypeScript. Общие типы API доступны в [`shared/api-v1.d.ts`](../shared/api-v1.d.ts) с задачи 10a.
- **Экраны:**
  - **Сопряжение** — сканер QR-кода, повторное подключение, отключение.
  - **Статус** — эфир, площадки, ошибки, кнопки «Проверить сейчас» и «Тестовое сообщение».
  - **Сообщение** — текст в анонс, своё превью (фото из галереи или камеры), предпросмотр анонса и сообщения об окончании.
  - **Настройки** — основные поля: тестовый режим, площадки, тайминги. Секреты с телефона не меняются.
  - **Лог** — последние строки.
- Светлая и тёмная тема по системе.
- **Если бот недоступен** (компьютер выключен или нет сети), приложение показывает это явно, а не бесконечную загрузку.

### 6. Сборка и выпуск

- **Android:** `expo prebuild` + Gradle в GitHub Actions в том же workflow, что и десктоп (`.github/workflows/release.yml`). `.apk` подписывается ключом из секретов репозитория и прикладывается к релизу рядом с `.dmg` и `.exe`.
- **iOS:** локальная сборка через Xcode для личного использования. TestFlight и App Store — после покупки Apple Developer.
- Версия приложения совпадает с версией бота. Приложение проверяет совместимость по версии API при подключении.

### 7. Тесты

- **API v1 и сопряжение:** vitest — коды, токены, отзыв, 401 без токена, ограничение частоты.
- **Приложение:** Jest + React Native Testing Library — экраны и обработка недоступности бота.
- **Вручную:** Android-телефон через Tailscale — сопряжение, все экраны, загрузка фото, push на тестовом эфире (`DRY_RUN=true`).

## Риски

- **Безопасность.** Открывая бота наружу, легко ошибиться. Поэтому доступ только через приватную сеть и только с токеном, а секреты через API не отдаются.
- **iOS без платного аккаунта** почти непригоден: переустановка каждые 7 дней, нет push, а в режиме «только Discord» нет и дублирующих сообщений.
- **Вынос `shared/`** может сломать сборку десктопа (electron-builder, asar). Поэтому он делается отдельной задачей с проверкой `dist:mac` и `dist:win`.
- **Компьютер с ботом должен быть включён** и не спать, иначе приложению не к чему подключаться. Это решает только перенос бота на сервер.

## Принятое решение

Нативное Android-приложение на React Native + Expo. iOS — по мере появления платного аккаунта.

**Telegram Mini App отклонён** (оценка 3–5 дней): он требует Telegram и не подходит для режима «только Discord». Для контекста, чем он был хорош:

- Панель открывается прямо в Telegram на телефоне, вход по аккаунту Telegram, без паролей и сопряжения.
- Не нужны магазины приложений и платные аккаунты, одинаково работает на Android и iOS.
- Интерфейс переиспользуется из веб-панели.
- Нужен публичный HTTPS-адрес бота (Cloudflare Tunnel или сервер), а push заменяют сообщения бота в Telegram.
