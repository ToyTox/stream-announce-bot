# Для разработчиков

[English](development.en.md) · **Русский**

Инструкция для пользователя приложения — в [README](../README.md).

## Стек

- **Node.js 22** с TypeScript (ESM)
- **axios** — HTTP-запросы к площадкам и Telegram
- **better-sqlite3** — локальная база состояния
- **Electron** + **electron-builder** — десктопное приложение и его установщики
- **node:http** — веб-панель, без фреймворков и сборки фронтенда
- **vitest** — тесты

## Установка из исходников

```bash
npm install
cp .env.example .env
```

Заполните `.env` (см. «Настройка бота» в [README](../README.md#настройка-бота) и таблицу переменных ниже) или запустите бота и заполните настройки в веб-панели.

## Запуск

### Рабочий режим — бот анонсирует стримы

```bash
npm run build
npm start
```

Запускает собранный JavaScript из `dist/` вместе с веб-панелью. Бот работает, пока открыт терминал, и не перезапускается от правок файлов.

После изменения кода (в том числе после `git pull`) остановите бота (Ctrl+C) и повторите `npm run build` и `npm start`. Состояние эфира хранится в базе, поэтому перезапуск посреди стрима не приведёт к повторному анонсу.

### Режим разработки — правка кода

```bash
npm run dev
```

Запускает TypeScript напрямую и перезапускает бота при каждом сохранении файла в `src/`. Сборка не нужна.

Чтобы во время разработки не отправлять сообщения в группу, поставьте `DRY_RUN=true` — анонсы будут только печататься в терминал — или укажите в `TELEGRAM_CHAT_ID` свой user ID, чтобы они приходили вам в личку.

### Что выбрать

| Задача | Команда |
|--------|---------|
| Бот работает и анонсирует ваши стримы | `npm run build` + `npm start` |
| Меняете код или шаблон сообщений | `npm run dev` |
| Бот в фоне с иконкой в строке меню | готовое приложение из Releases или `npm run desktop` |

Не запускайте два экземпляра одновременно: они работают с одной базой и одним токеном, поэтому могут отправить анонс дважды и перехватывать друг у друга команды.

### Работа на Mac без сна

Если бот крутится на MacBook, который работает с закрытой крышкой, запретите сон:

```bash
sudo pmset -a disablesleep 1   # вернуть: sudo pmset -a disablesleep 0
```

Блокировка экрана и выключенный дисплей боту не мешают — останавливает его только сон системы. С этой настройкой не убирайте MacBook в сумку: он не уснёт и будет разряжаться.

## Десктопное приложение

«Анонсы стримов» — Electron-оболочка: бот работает в фоне, в строке меню (трее) висит иконка со статусом, а окно показывает ту же веб-панель.

```bash
npm install
npm run desktop
```

Команда собирает приложение в `dist-desktop/` и запускает его. При первом запуске (или если настройки с ошибкой) окно открывается на вкладке «Настройки»; дальше приложение живёт в трее, а окно открывается по пункту «Открыть панель».

**Меню в трее**

| Пункт | Что делает |
|-------|-----------|
| Статус (неактивная строка) | «Эфира нет», «● Эфир идёт с 18:00 · Twitch, YouTube», «Тестовый режим» или «Бот не запущен: <ошибка>» |
| Открыть панель | Показывает окно |
| Проверить сейчас | Внеочередная проверка площадок |
| Запускать при входе в систему | Автозапуск приложения (запускается скрыто, в трее) |
| Не давать системе засыпать | Пока включено, система не уходит в сон из-за бездействия; на закрытую крышку не влияет |
| Выйти | Останавливает бота и закрывает приложение |

Иконка меняется: кольцо — эфира нет, закрашенный круг — эфир идёт, с «!» — тестовый режим или ошибка проверки площадки, перечёркнутое — бот не запущен. Закрытие окна крестиком только прячет его (на macOS пропадает и значок в Dock): бот продолжает работать. Уведомления приходят, когда анонс отправлен, эфир завершён или анонс не удалось отправить.

**Обновление.** Приложение раз в сутки проверяет последний релиз на GitHub; если есть новее, в меню в трее появляется «Доступна версия X — скачать» и приходит одно уведомление. Скачайте новый установщик и установите поверх: настройки и база сохраняются. Текущая версия видна в меню в трее и в шапке панели.

**Переход с версии 0.1.0.** Она ставилась в папку пользователя без прав администратора: новый установщик сам удалит старую копию и поставит новую в `Program Files`; настройки и база сохраняются, автозапуск начнёт вести на новую копию при первом запуске. Если после установки в «Установке и удалении программ» осталось две записи или на рабочем столе два ярлыка, удалите старую копию (ту, что в папке пользователя) вручную: настройки и база при этом сохранятся. Так бывает, когда права администратора в окне UAC выдавала другая учётная запись.

**Где лежат данные.** `.env` и база `bot.db` — в папке приложения: `~/Library/Application Support/Анонсы стримов/` (на Windows `%APPDATA%`, на Linux `~/.config`). Данные хранятся отдельно для каждого пользователя Windows (в `%APPDATA%` текущего пользователя), даже если приложение установлено для всех, поэтому запускайте бота под одной учётной записью. Если права администратора при установке выдавала другая учётная запись, ярлык на рабочем столе может появиться у неё; данные всё равно хранятся у того, кто запускает приложение. Файл `.env` в корне проекта приложение не читает. Если `DATABASE_PATH` не задан, база создаётся рядом с `.env`.

**Перенос настроек.** Во вкладке «Настройки» кнопка «Импортировать .env…» заменяет настройки приложения выбранным файлом: он проверяется, и если в нём ошибка, ничего не меняется. Так можно перенести настройки из терминального режима.

**Одна копия.** Повторный запуск не создаёт второго бота, а показывает окно уже работающего.

**Не запускайте вместе с `npm start`.** У приложения своя база: два бота с одним токеном не знают друг о друге и отправят анонс дважды. Выберите один способ запуска.

**Закрытая крышка MacBook.** Пункт «Не давать системе засыпать» не мешает сну при закрытой крышке — для этого по-прежнему нужен `sudo pmset -a disablesleep 1` (см. «Работа на Mac без сна»).

**Нативный модуль.** better-sqlite3 с версии 13 собран на Node-API, поэтому один и тот же бинарник работает и в Node (`npm test`, `npm start`), и в Electron — пересборка под Electron не нужна. Если на вашей платформе загрузился неподходящий бинарник, пересоберите модуль: `npx electron-rebuild -f -w better-sqlite3` (для Electron) или `npm rebuild better-sqlite3` (для Node). Скрипт `scripts/desktop.mjs` запускает Electron без переменной `ELECTRON_RUN_AS_NODE`, которую выставляет терминал VS Code.

Для проверок можно задать отдельную папку данных: `STREAM_BOT_USER_DATA=/tmp/bot-test npm run desktop`.

## Выпуск версии

Установщики собирает GitHub Actions, вручную ничего загружать не нужно:

```bash
npm version patch        # 0.1.0 → 0.1.1 — исправления
npm version minor        # 0.1.0 → 0.2.0 — новые возможности
git push --follow-tags   # отправляет коммит и тег — запускает сборку
```

Каждая команда `npm version` меняет `package.json` и ставит тег `vX.Y.Z`. Пока версия начинается с `0.`, продукт считается не готовым; `1.0.0` — первая стабильная версия (`npm version major`).

Самый первый релиз — уже выставленная версия `0.1.0`, тег ставится вручную:

```bash
git tag v0.1.0
git push origin v0.1.0
```

Через 10–15 минут в [Releases](https://github.com/ToyTox/stream-announce-bot/releases) появится релиз с тремя файлами (`arm64.dmg`, `x64.dmg`, `x64.exe`) и списком изменений из коммитов. Сборка не запустится, если версия в теге не совпадает с `package.json`. Вкладка Actions → Release → «Run workflow» делает пробную сборку без релиза: файлы остаются в артефактах запуска.

Локальная пробная сборка: `npm run dist:mac` или `npm run dist:win` (результат в `release/`). Если терминал выставляет `ELECTRON_RUN_AS_NODE` (VS Code), запускайте с `env -u ELECTRON_RUN_AS_NODE`.

## Веб-панель

Вместе с ботом запускается панель — откройте **http://localhost:3210**. Ссылка также печатается в терминале при запуске.

- Панель слушает только `127.0.0.1`: из сети и с телефона она недоступна, запросы с чужих сайтов отклоняются. Пароля нет — всё, что видно в панели, и так лежит в `.env` на этом компьютере.
- Сохранение настроек пишет `.env` (комментарии сохраняются). В начале каждой группы настроек — свёрнутая инструкция «Как получить» (работает без интернета), сверху — ссылка на README.
- Порт меняется через `WEB_PORT`, выключить панель — `WEB_ENABLED=false`. В десктопном приложении панель работает всегда, а если порт занят, берётся свободный.

## Язык интерфейса и анонсов

Интерфейс (панель, меню в трее, уведомления, ответы бота в личке) и тексты анонсов бывают на русском и английском. Языки настраиваются отдельно:

- **`APP_LANGUAGE`** — язык интерфейса: `ru`, `en` или пусто. Пусто — по языку системы (в панели — по языку браузера): русский для русских локалей, английский для остальных.
- **`ANNOUNCE_LANGUAGE`** — язык постоянных фраз анонса и итога эфира в Telegram и Discord (приветствие, благодарность, длительность). Пусто — тот же, что у интерфейса. Зрители канала могут говорить не на языке стримера, поэтому язык анонса задаётся отдельно. Название стрима и текст врезки не переводятся.

Сменить язык интерфейса можно переключателем в шапке панели (бот при этом не перезапускается) или полем «Язык интерфейса» во вкладке «Настройки»; язык анонса — полем «Язык текстов анонса» там же. Выбор сохраняется в `.env`. Команды бота (`/text`, `/image`…) на всех языках одинаковые, меняются только ответы.

Новый язык добавляется файлом словаря в `src/i18n/` (копия `en.ts` с переведёнными текстами) и одной строкой в `DICTIONARIES` в `src/i18n/index.ts`; разметку править не нужно. Тест проверяет, что в новом словаре есть все ключи.

## Поведение

- **Первая замеченная площадка** открывает эфир, но анонс уходит не сразу: бот ждёт 90 секунд (`ANNOUNCE_GRACE_MS`), пока подключатся остальные площадки из OBS.
- **Одно сообщение** со ссылками на все площадки, которые в эфире на момент отправки.
- **Название и игра** берутся только с Twitch (`PRIMARY_PLATFORM`): на других площадках они могут отличаться. Если Twitch не в эфире, название будет «Трансляция».
- **Превью**: своё (из лички или панели), если задано, иначе превью Twitch. Если нет ни того, ни другого, анонс уходит текстом.
- **Telegram и Discord независимы**: у каждой площадки доставки своё состояние в базе. Сбой одной не мешает другой и не повторяет уже доставленное; недоставленная повторяется в следующих проверках, пока эфир идёт. Постоянная ошибка Discord (вебхук удалён или неверен: 400, 401, 403, 404) повторов не вызывает. Итог эфира уходит только туда, куда дошёл анонс. Площадка, подключённая посреди эфира, догоняющего анонса не получает.
- **Discord**: сообщения приходят карточкой (embed) с теми же ссылками; `@everyone` из названия никого не пингует. Картинку бот прикладывает файлом (`multipart`, в embed `attachment://…`): своя из `/image` и панели, иначе превью Twitch (только если приоритетная площадка — Twitch), иначе сообщение идёт текстом. Превью YouTube и VK Video в Discord не попадают. Если свою картинку получить не удалось или превью Twitch не скачалось (таймаут, не картинка, больше 10 МиБ), анонс уходит без картинки с предупреждением в логе; доставка при этом засчитывается. Свою картинку Discord получает из локальной копии (см. ниже), а не из Telegram. Текст из `/text` показывается как есть, без форматирования.
- **Локальная копия своей картинки**: файлы `announce-image.bin` (байты) и `announce-image.json` (`file_id` и тип) лежат в папке данных, то есть в каталоге `DATABASE_PATH` (в десктопном приложении — userData). Копия действует, пока её `file_id` совпадает с сохранённым в базе. Панель и `/image` сохраняют её сразу (панель — с исходным типом png/jpeg/webp, Telegram отдаёт jpeg); если копии нет (картинка задана до обновления или скачивание не удалось), при первом обращении (анонс или предпросмотр) её один раз докачивают из Telegram. `/image -`, `/image_clear` и сброс в панели удаляют файлы. Логика чтения, записи и докачки — в `src/announceImage.ts`.
- **Анонс не редактируется**: если площадка потом упала, ссылка остаётся; если подключилась позже — в анонс не попадает.
- **Окончание**: эфир закрывается, если все площадки молчат дольше 3 минут (`OFFLINE_GRACE_MS`) — это защита от разрывов. После этого уходит отдельное сообщение с длительностью и ссылками на каналы с записями. Выключается `ANNOUNCE_END=false`.
- **Ошибка проверки** площадки (сеть, сбой API) не закрывает эфир — закрывает только явный ответ «офлайн».
- **Перезапуск** посреди эфира, в том числе из панели, не приводит к повторному анонсу.
- **Язык**: постоянные фразы анонса и итога эфира идут на языке `ANNOUNCE_LANGUAGE`, см. «Язык интерфейса и анонсов». При `ANNOUNCE_LANGUAGE=en` они на английском («Hello everyone», «Stream ended, it lasted …»).

В Discord состав сообщений тот же, но это карточка с Markdown-ссылками. VK Video идёт вместе с VK Live.
